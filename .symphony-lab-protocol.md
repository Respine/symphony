# Symphony lab protocol

Follow this protocol for every issue. Use the injected `linear_graphql` tool for all Linear reads and writes. Read `.codex/skills/linear/SKILL.md` before the first Linear mutation.

## Communication language

All Linear comments, workpad text, progress reports, blocker reports, and final messages must use Simplified Chinese. Follow these exact style rules:

用最常见的普通话名词。
能少字就少字，不过度解释。
可以牺牲语法换取极简表达。
消灭不必要的结构和包装用语。
人一眼就能看懂的表达，尽量不用术语，杜绝黑话和 buzzword。

## Comments

- Maintain exactly one mutable comment headed `## Codex Workpad`.
- The workpad is the only comment that may be edited. Never delete it.
- Every other status or progress comment is append-only: create a new comment and never edit or delete it.
- Keep append-only comments short and in Chinese. Post at acceptance, meaningful phase boundaries, blocking, ready-for-review, merge start, and completion. During work lasting over 15 minutes, post one short checkpoint comment every 15 minutes. Do not post command-by-command noise.
- Use ISO timestamps with the Asia/Shanghai offset.

Workpad sections:

```markdown
## Codex Workpad

### Plan
- [ ] ...

### Acceptance criteria
- [ ] ...

### Progress
- current facts and decisions

### Validation
- commands and results

### Handoff
- commit, PR, risks, remaining work
```


## Long-running work

- If a command, training, benchmark, remote job, or wait may run over 5 minutes, first write a background progress-sync script.
- Before starting, use `linear_graphql` once to find the Workpad comment ID and save it for the script.
- The script reads a local status file or job log and updates only the existing `## Codex Workpad` every 5 minutes through `http://127.0.0.1:8787/graphql`.
- Sync content: timestamp, running stage, latest evidence, blocker if any, next checkpoint.
- Do not use model turns to poll and repeat the same status. During a long job, append one short checkpoint comment every 15 minutes with new evidence and the next checkpoint.
- Stop the script at a phase boundary, blocker, ready-for-review, or before final handoff; then make one final Workpad update.

## Status flow

### Todo

1. Move to `In Progress` before doing work.
2. Find or create the workpad and write the plan and acceptance criteria.
3. Append a new comment: `▶ Accepted by runner:lab` with timestamp and the first planned checkpoint.

### In Progress

1. Resume from the current workspace and workpad; do not restart completed work.
2. Keep the workpad current by editing it.
3. For any expected wait over 5 minutes, write and launch a background progress-sync script.
4. Let the script update the Workpad every 5 minutes; do not spend model turns polling or rewriting the same status.
5. Append a short comment at meaningful phase boundaries. If a phase lasts over 15 minutes, post a checkpoint comment every 15 minutes with new facts and the next checkpoint.
6. For code changes, commit, push, open or update a PR, attach it to the issue, resolve actionable review feedback, and require passing checks.

### Ready for human review

When acceptance criteria and validation are complete:

1. Update the workpad handoff with commit, PR, validation, risks, and remaining human checks.
2. Append a completion comment starting with the Yi Qiu profile URL, then `✅ READY FOR HUMAN REVIEW`, result summary, validation evidence, and PR or artifact links.
3. Move the issue to `Human Review`.

Do not modify code or issue content while the issue is in `Human Review`. A human moves it to `Merging` when approved, or `Rework` when changes are required.

### Rework

1. Re-read the issue and all new comments.
2. Move to `In Progress`.
3. Preserve the existing workpad. Add a new attempt section and rewrite only its live plan, criteria, progress, validation, and handoff sections.
4. Append `↩ Rework accepted by runner:lab` with what will change this attempt.
5. Execute the normal flow and return to `Human Review` only after revalidation.

### Merging

1. Append `⏳ Merge started by runner:lab`.
2. Read and follow `.codex/skills/land/SKILL.md`. Recheck review comments and required checks. Do not bypass branch protection or force merge.
3. After the PR is merged, update the workpad, append a final comment starting with the Yi Qiu profile URL and `✅ COMPLETED`, including merge and validation evidence, then move to `Done`.

### Blocked

Use this only after reasonable in-scope attempts fail because access, permission, a secret, hardware, external evidence, or a required human decision is missing.

1. Update the workpad with the blocker and attempted fixes.
2. Append a new comment starting with the Yi Qiu profile URL and `⛔ BLOCKED — runner:lab`.
3. State: blocker, impact, what was tried, and the exact action needed to unblock.
4. Move to `Human Review`. Never mark blocked work as complete.
